# Saved itinerary navigation

The Saved trips card action opens a read-only map of the owned trip's persisted itinerary. Every new endpoint calls existing traveler authentication and the owned trip repository before contacting a provider. No itinerary, completion, visit, rating or GPS-history writes are introduced. Exact place choices belong only to the open map session.

Endpoints under /api/navigation/trips/:id:
- GET /map returns persisted day dates and ordered activities.
- POST /activity accepts dayIndex/activityIndex and optional explicit query/placeId selection.
- POST /day-route accepts dayIndex, a supported walking/cycling/driving mode and explicit selections; stops follow the saved order.
- POST /weather accepts the saved activity selection and optional current=true. Dates, times and coordinates are taken from the owned itinerary/place resolution, not caller overrides.

## Existing providers and setup

Leaflet/OpenStreetMap tiles and the existing GPS and OSRM guidance hooks are reused. The existing NAVIGATION_ROUTING_BASE_URL can target an OSRM installation exposing routed-foot, routed-bike and routed-car. An unavailable profile returns an error, not a working substitute. Road snapping beyond 100 m is rejected for itinerary routes. A dashed preview is explicitly not navigable. Public routing is shared across users at one request per 1.1 seconds; routes cache for five minutes. Attribution includes a Fix the map link. [FOSSGIS service policy](https://routing.openstreetmap.de/about.html), [OSRM route API](https://project-osrm.org/docs/v5.24.0/api/).

Explicit place search reuses DESTINATION_GEOCODER_URL and the existing Nominatim queue, application User-Agent, Retry-After handling and country filter. Queries contain the full venue, city and country; candidates must have matching city/country and plausible coordinates, and require a user choice. This is not autocomplete or bulk geocoding. Search results cache for 24 hours (up to seven days on provider failure). The public service permits moderate, directly requested use only, at an aggregate maximum of one request per second. For a larger or multi-instance deployment, configure a suitable geocoder and coordinate throttling across instances. [Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/).

The existing Wikidata/Wikipedia/Commons reference service supplies exact landmark IDs and licensed photographs. Saved photographs covered by a valid server grounding proof can be reused directly; unsigned images must be checked against the exact catalog entity, matching coordinates and destination. City covers, flags and unmatched photos are excluded. Provider failures get a five-minute feature-specific negative cache; the original reference cache retains its six-hour freshness and 24-hour stale window. Without a verified image, a neutral Place photo unavailable placeholder remains. Creator, license, source and crop disclosure accompany photos. No Unsplash venue searches or new photo provider were added. [Commons image metadata API](https://www.mediawiki.org/wiki/API:Imageinfo).

Weather uses the existing Open-Meteo provider through a scoped hourly adapter. The selected venue coordinates are requested with timezone=auto and Unix timestamps; local schedule matching uses the returned IANA timezone, including DST. Nearby stops share cached grid data (15-minute freshness, up to one-hour stale fallback). The provider's actual returned coverage determines availability; future dates never use today's conditions implicitly. Forecasts outside coverage, missing precise times, stale current validity, missing fields, wrong-location grids, outages and Retry-After are handled explicitly. Public requests are capped at 200/minute, 500/hour and 4,000/day for this feature, leaving room for weighted 16-day requests and other existing weather usage. Application-wide public-service capacity still needs monitoring.

For evaluation/non-commercial use, no new weather credential is required. For commercial weather use, obtain an Open-Meteo subscription and set OPEN_METEO_API_KEY in the backend environment; this feature uses the customer endpoint, and the key never reaches the browser. Existing unrelated daily-weather integrations are unchanged. The hourly best-match response does not supply a single model publication timestamp: the panel displays the provider's forecast/current validity time and retrieval time, and states that provider update time is not supplied. It never invents an update timestamp. [Forecast documentation](https://open-meteo.com/en/docs), [model updates](https://open-meteo.com/en/docs/model-updates), [terms](https://open-meteo.com/en/terms), [paid endpoint setup](https://open-meteo.com/en/pricing).

Live location starts only from Use live GPS, reports accuracy, supports a manual chosen origin and clears tracking when navigation ends, the selected activity/day changes, the dialog closes or the tab is hidden. Routes and provider instructions are estimates, without live traffic or guaranteed arrival/entrance accuracy. TravelMate does not save GPS history.
